Update `.gitignore` to un-ignore the `tests/` directory and test file extensions. The current `.gitignore` has two blocking patterns:

1. `*test*` on line 21 matches the `tests/` directory name itself
2. `*.bed` on line 10 and `*.vcf` on line 11 match test data files

**CRITICAL: Order matters.** Git processes `.gitignore` top-to-bottom. Later rules override earlier ones. Exceptions MUST appear immediately BEFORE the rules they override. The `*test*` rule at line 21 is the primary blocker for the `tests/` directory, so `!/tests/` and `!/tests/**` MUST be placed immediately before that line.

The file-extension exceptions (`!/tests/**/*.vcf`, `!/tests/**/*.bed`, etc.) must also appear after the `*.bed` and `*.vcf` rules they override. Since the `*test*` block is already below those rules, placing everything together immediately before `*test*` satisfies both ordering requirements.

The final `.gitignore` should look exactly like this:

```
# Ignore temporary files
*.tmp
*.log

# Ignore compiled binaries
*.o
*.out

# Ignore bedtools and bcftools temporary files
*.bed
*.vcf

# Ignore tes, output, ref, and tmp directories
/test/
/output/
/ref/
/tmp/
/stats/

# Allow tests directory and test data files
!/tests/
!/tests/**
!/tests/**/*.vcf
!/tests/**/*.vcf.gz
!/tests/**/*.vcf.gz.tbi
!/tests/**/*.bed
!/tests/**/*.fa
!/tests/**/*.fa.fai

# files with test in the name
*test*
```

**Key points:**
- `!/tests/` and `!/tests/**` are placed IMMEDIATELY before `*test*` (not before `*.bed`)
- The `!/tests/**` is required because git does not look inside an ignored directory -- both the directory and its contents must be explicitly un-ignored
- The file-extension exceptions (`!/tests/**/*.vcf`, etc.) override the `*.bed` and `*.vcf` rules above
- The `*test*` rule at the bottom still blocks files with "test" in their name OUTSIDE the tests/ directory

**Reference FASTA (mini_ref.fa):**

Per the locked decision: "Reference FASTA: extract 100kb subset from hs37d5.fa using samtools faidx, then re-index."

All synthetic VCFs use positions 10001-90000 (within the mini_ref.fa 1-100001 range). This makes mini_ref.fa usable for bcftools norm on all synthetic VCFs, keeping the test suite self-contained.

Extract from hs37d5.fa (which exists on disk at ref/hs37d5.fa but is gitignored):

```bash
# Extract chr22 100kb region from hs37d5.fa
samtools faidx ref/hs37d5.fa 22:1-100001 \
    | sed '1s/.*/\>22/' > tests/data/synthetic/mini_ref.fa

# Re-index the extracted FASTA
samtools faidx tests/data/synthetic/mini_ref.fa
```

This creates a FASTA with:
- Header: `>22`
- Sequence: 100001 bases of real chr22 sequence from hs37d5 (positions 1-100001)
- The .fai file will have: `22	100001	4	80	81` (approximately, depending on line wrapping)

**Why positions 1-100001 (not 16000000-16100000):** Using `22:1-100001` extracts the first 100kb of chr22. After renaming the header to `>22`, the FASTA contig covers positions 1-100001. Since all synthetic VCFs use positions 10001-90000, bcftools norm can validate REF alleles against this reference. If we had extracted 22:16000000-16100000, bcftools would see contig `22` with only 100001 bases but VCFs referencing positions 16000000+, which would be out of range.

**IMPORTANT:** If `ref/hs37d5.fa` is not available on the current machine, fall back to creating a synthetic FASTA:

```bash
echo ">22" > tests/data/synthetic/mini_ref.fa
python3 -c "
import random
random.seed(42)
bases = 'ACGT'
seq = ''.join(random.choice(bases) for _ in range(100001))
for i in range(0, len(seq), 80):
    print(seq[i:i+80])
" >> tests/data/synthetic/mini_ref.fa
samtools faidx tests/data/synthetic/mini_ref.fa
```

If using the fallback, the REF alleles in synthetic VCFs must be verified to match the generated sequence at each position. The hs37d5 extraction is strongly preferred.
