Update `.gitignore` to un-ignore the `tests/` directory and test file extensions. The current `.gitignore` has two blocking patterns:

1. `*test*` on line 21 matches the `tests/` directory name itself
2. `*.bed` on line 10 and `*.vcf` on line 11 match test data files

**CRITICAL: Order matters.** Git processes `.gitignore` top-to-bottom. Exceptions must appear BEFORE the rules they override.

Add these lines BEFORE the existing `*.bed` line (around line 9):

```
# Allow tests directory and test data files
!/tests/
!/tests/**
```

This un-ignores the entire `tests/` tree. The `!/tests/**` is needed because git does not look inside an ignored directory -- both the directory and its contents must be explicitly un-ignored.

Also add these lines BEFORE the `*test*` line to be explicit:

```
!/tests/**/*.vcf
!/tests/**/*.vcf.gz
!/tests/**/*.vcf.gz.tbi
!/tests/**/*.bed
!/tests/**/*.fa
!/tests/**/*.fa.fai
```

The final `.gitignore` should look like:

```
# Allow tests directory and test data files
!/tests/
!/tests/**

# Ignore temporary files
*.tmp
```

**Reference FASTA (mini_ref.fa):**

The synthetic VCFs will use chr22 genomic positions in the range 16000000-16100000. For bcftools norm to work on these VCFs, we need a reference where contig `22` covers at least those positions.

**Design decision (from RESEARCH.md Open Question 1):** Use chr22:16000000+ coordinates in synthetic VCFs. For tests that need bcftools norm on synthetic VCFs, the mini_ref.fa will NOT work (positions out of range for its 100kb size). However, most Phase 3 tests test FILTERING (not normalization), so mini_ref.fa is sufficient for those. The multiallelic.vcf will use positions 10100-30300 (small coordinates valid within mini_ref.fa) so that bcftools norm splitting can be tested. Integration tests with real data use the full reference downloaded by generate_test_data.sh.

Create `tests/data/synthetic/mini_ref.fa` as a hand-crafted FASTA:
- Header: `>22`
- Sequence: 100001 bases of realistic-looking (but synthetic) DNA sequence
- Use a repeating pattern like `ACGTACGTNN` repeated to fill 100001 characters
- Format: 80 characters per line (standard FASTA line width)

Generate the FASTA programmatically:

```bash
echo ">22" > tests/data/synthetic/mini_ref.fa
# Generate 100001 bases: repeating ACGTACGTNN pattern
python3 -c "
seq = 'ACGTACGTNN' * 10001
seq = seq[:100001]
for i in range(0, len(seq), 80):
    print(seq[i:i+80])
" >> tests/data/synthetic/mini_ref.fa
```

Then create the FASTA index:
```bash
samtools faidx tests/data/synthetic/mini_ref.fa
```

This creates `mini_ref.fa.fai` with one line: `22	100001	4	80	81`

If samtools is not available in the current environment, create the .fai file manually:
```
22	100001	4	80	81
```
Where: name=22, length=100001, offset=4 (bytes after ">22\n"), bases_per_line=80, bytes_per_line=81.

**BED files:**

Create `tests/data/include_regions.bed` (tab-separated, no header):
```
22	16010000	16030000
22	16040000	16060000
22	16070000	16090000
```
These 3 non-overlapping regions cover parts of the test range. Synthetic variants at positions 16010100-16060100 fall within included regions. Variant at 16090000+ would be outside.

Create `tests/data/exclude_regions.bed` (tab-separated, no header):
```
22	16020000	16025000
22	16080000	16085000
```
These 2 regions overlap with the include regions. Variants in 16020000-16025000 will be annotated as EXCLUDE_REGION even though they are also in INCLUDE_REGION -- the pipeline handles both annotations and filtering logic decides.

**Genome file:**

Create `tests/data/hg19_chr22.genome` (tab-separated, no header):
```
22	51304566
```
This is the chr22 length from hg19/GRCh37. Required by `bedtools slop` to prevent extending BED intervals beyond chromosome boundaries.

**IMPORTANT:** All BED and genome files must use actual TAB characters as delimiters, not spaces. Use printf or heredoc with literal tabs.
