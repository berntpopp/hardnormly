Run the current hardnormly.sh on each synthetic VCF to produce expected filtered outputs. These become the regression test baseline.

**REFERENCE FASTA:** Use `tests/data/synthetic/mini_ref.fa` as the reference for expected output generation. Since all synthetic VCFs use positions 10001-90000 (within mini_ref.fa's 100001-base contig), bcftools norm can validate REF alleles and perform normalization correctly. This makes the expected output generation fully self-contained -- no dependency on gitignored ref/hs37d5.fa.

**Check first:** Run `./hardnormly.sh --help` to understand which flags are required vs optional.

**Expected output generation commands:**

```bash
# Record baseline commit
echo "# Generated by hardnormly.sh at commit: $(git rev-parse HEAD)" > tests/data/expected/BASELINE.txt
echo "# Date: $(date -u +%Y-%m-%dT%H:%M:%SZ)" >> tests/data/expected/BASELINE.txt
echo "# hardnormly.sh version: $(grep '^version=' hardnormly.sh | head -1)" >> tests/data/expected/BASELINE.txt
echo "# Reference: tests/data/synthetic/mini_ref.fa" >> tests/data/expected/BASELINE.txt

REF_FASTA="tests/data/synthetic/mini_ref.fa"

# GATK samples
for SAMPLE in A B; do
    ./hardnormly.sh \
        -v "tests/data/synthetic/gatk_sample_${SAMPLE}.vcf.gz" \
        -f "${REF_FASTA}" \
        -b tests/data/include_regions.bed \
        -e tests/data/exclude_regions.bed \
        --filters-file defaults/gatk_filters.txt \
        -g tests/data/hg19_chr22.genome \
        -o "tests/data/expected/gatk_sample_${SAMPLE}_filtered.vcf.gz" \
        --auto-index
done

# Freebayes samples
for SAMPLE in A B; do
    ./hardnormly.sh \
        -v "tests/data/synthetic/freebayes_sample_${SAMPLE}.vcf.gz" \
        -f "${REF_FASTA}" \
        -b tests/data/include_regions.bed \
        -e tests/data/exclude_regions.bed \
        --filters-file defaults/freebayes_filters.txt \
        -g tests/data/hg19_chr22.genome \
        -o "tests/data/expected/freebayes_sample_${SAMPLE}_filtered.vcf.gz" \
        --auto-index
done
```

**IMPORTANT:** Read hardnormly.sh to understand its exact CLI flags. The flags above are based on the CLAUDE.md documentation. Adjust as needed:
- `-v` = input VCF
- `-f` = reference FASTA
- `-b` = include BED
- `-e` = exclude BED
- `--filters-file` = filter definitions file
- `-g` = genome file
- `-o` = output VCF
- `--auto-index` = auto-create tabix index on output

If hardnormly.sh does not support `--auto-index`, manually index each output:
```bash
bcftools index -t "tests/data/expected/gatk_sample_A_filtered.vcf.gz"
```

**After generation, validate each expected output:**

```bash
for vcf in tests/data/expected/*_filtered.vcf.gz; do
    echo "=== $vcf ==="
    bcftools view "$vcf" -Oz -o /dev/null && echo "Format: OK" || echo "Format: FAILED"
    echo "Records: $(bcftools view -H "$vcf" | wc -l)"
    echo "Filters applied:"
    bcftools query -f '%FILTER\n' "$vcf" | sort | uniq -c
done
```

Each expected output should have FILTER tags applied -- NOT all PASS. If all records show `.` or `PASS` in FILTER, something is wrong with the filter pipeline or the synthetic VCF field values.

**Troubleshooting if all variants pass:**
1. Check if `bcftools +fill-tags` is computing VAF: `bcftools +fill-tags input.vcf.gz -- -t FORMAT/VAF | bcftools query -f '[%VAF]\n'`
2. Check if filter expressions match field names: compare filter file expressions with VCF INFO/FORMAT headers
3. Run with `--debug` flag if hardnormly.sh supports it to see the filter pipeline being constructed
4. Try running a single filter manually: `bcftools filter -e 'FORMAT/DP<10 && GT!="hom"' input.vcf.gz`
